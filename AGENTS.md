# radio-86rk-case — правила для агентов (Claude Code и Codex)

Здесь корпус Радио-86РК: текущая принятая версия и будущие. Модель самого компьютера (плата, переключатели, колпачки) — в `model/`, правила работы с ней — в `CLAUDE.md`, раздел «Модель компьютера». Плата — в соседнем репозитории `radio-86rk`, отсюда её только читать.

Прямые актуальные решения пользователя важнее истории и отчётов. Состояние, открытые вопросы и журнал решений — `case/PROJECT-STATE.md`.

## Навыки
Техника — в навыках маркета, здесь только числа и решения этого проекта. Значения ниже переопределяют значения навыков по умолчанию.
- `dv-freecad-print-workflow`: `cad-print-workflow` (этапы), `freecad-zone-edit` (метод зоны и сторожа), `freecad-headless-analysis` (проверки числами), `freecad-gui-macro` (FCStd для человека, снимки), `freecad-mcp-operations` (только открытое окно пользователя), `bambu-print-preparation`.
- `dv-agent-controller`: `guarding-autonomous-runs` (гибкое правило «5 минут», кандидат, координатор и исполнитель).
- Локальная правка: `case/rounds/<uuid>/LOCAL-PLAN.md` с выжимкой чисел, затем исполнитель `freecad-worker` (проектный, `.claude/agents/`) без всей переписки. Отчёт и проверку результата делает координатор.

## Версии
- Текущая принятая версия — `case/CURRENT.path`. Принятые версии лежат в `case/accepted/<дата>-<имя>/` (только чтение, `MANIFEST.sha256`); их не перезаписывать. Новая версия становится принятой только по прямому решению пользователя.
- Принятая сборка FCStd хранится в git (облегчённая, без истории построений, ~20 МБ). Файл больше 50 МБ в git не класть: облегчить (метод очистки — `case/accepted/2026-11-06-clean/evidence/REPORT.md`) или обсудить с пользователем.
- Перед работой — `git fetch`: в репозиторий могут писать другие среды.
- **Репозиторий публичный: никаких абсолютных путей и e-mail в файлах, включая содержимое FCStd/3mf** (решение пользователя 06.11.2026).
  - В свойствах объектов (заметки о происхождении), отчётах и манифестах — только пути от корня репозитория или `<архив>/…`.
  - Страж — `.githooks/pre-commit` → `tools/check_private.py --staged`: он смотрит и внутрь FCStd.
  - Включить один раз на клон: `git config core.hooksPath .githooks`.
  - Обходить страж (`--no-verify`) нельзя.
- Рабочие раунды `case/rounds/` в git не попадают.
- **Выгруженные детали (BREP, STL, STEP) — производные от текущего принятого FCStd.** В git их не хранить. Без проверки соответствия не использовать: они могут не совпадать со сборкой (решение пользователя 06.11.2026).
  - Куда: `.build/parts/<первые 12 знаков SHA-256 принятого FCStd>/` — по мере надобности, в git не попадает (`.build/` в `.gitignore`). Папка от другого SHA — устаревшая.
  - Выгрузка — `tools/fcq tools/extract_parts.py` (`STL=1` — ещё и сетки печати): форма как в сборке (`Part.getShape(obj, "", transform=True)`), рядом `parts-manifest.json` с SHA-256 исходного FCStd, SHA-256 каждого файла и числами (грани, рёбра, V, S, bb), сверенными с объектом сборки при выгрузке.
  - Перед использованием — `$CAD_PY -I tools/parts_check.py` (код 0 — `fresh`): сверяет SHA источника и файлов с манифестом (доли секунды). `stale` или `missing` — выгрузить заново (~25 с).
  - Проверка по непроверенным или устаревшим деталям — NOT RUN, не PASS.

## Запуск FreeCAD
- Без GUI — только `tools/fcq script.py` (тихая обёртка с профилем CAD-AI; вывод — только `RESULT {json}`). Пути этой машины (launcher, профиль, интерпретатор Python для вспомогательных скриптов) — в `tools/local.env`, файл не отслеживается; образец — `tools/local.env.example`.
- GUI — только отдельным запуском макроса с профилем CAD-AI (`--user-cfg/--system-cfg`); пользователю файл открывать через `open -a /Applications/FreeCAD.app <файл>`. Окно FreeCAD — один исполнитель за раз, по разрешению координатора.
- После любой GUI-сессии — `git status`: FreeCAD может перезаписать открытый `.FCStd` без сохранения.
- Журнал попыток — `evidence/ATTEMPTS.log`; замер контекста — `evidence/CONTEXT-STATS.json` (`start`/`end`, недоступное — `null` с причиной).

## Временно, пока не установлены навыки 2.0.1
Эти правила уже записаны в ветке маркета `skills-2.0.1-additions`. Раздел удалить после установки `dv-freecad-print-workflow` 2.0.1 и `dv-agent-controller` 0.4.1.
- Только встроенные средства FreeCAD. numpy, scipy, pythonocc и свои алгоритмы — лишь если встроенного аналога нет; каждый такой случай — в «Исключения» отчёта.
- Без разрешения в плане `toNurbs` всего тела запрещён, так же как глобальные Refine/ShapeFix/Sewing и USD без keepShapes.
- FreeCAD 1.1.4: шов — `Edge.isSeam(face)`, вырожденное ребро — `Edge.Degenerated`; `fixVertexPosition` возвращает только bool.
- Ошибка, похожая на успех. Под freecadcmd `if __name__ == "__main__"` не срабатывает, поэтому `main()` вызывать на уровне модуля. Исключение может дать код 0, а stdout теряется без `flush`. Поэтому `main()` — в `try/except` с `RESULT {"error":…}`; о прогоне судить по строке `RESULT` и свежим файлам, не по коду 0.
- Новой проверке верить только после того, как она упала на подброшенной ошибке (тавтологии, старые входные файлы).
- После GUI-сессии FreeCAD может перезаписать открытый FCStd без `save()`. Открывать только копии и сверять SHA-256 исходников до и после; в git — `git status`.

## Числа и решения проекта
- Допуск ребра: «отклонение × 1,1», потолок 5e-4 (05.11.2026); уменьшать можно.
- Порог изменения 0,001 % (30.10.2026). Полная политика — `case/policies/SIMPLIFICATION-RULES.md`.
- Сетка печати 0,015 / 0,08 / `Relative=False`.
- Коллизии — только корпус ↔ детали: верх, низ, крышечка и ножки против клавиш, платы, компонентов и U25. Детали компьютера между собой не проверять (05.11.2026). Ход клавиш 4 мм по −Z, колпачок движется со штоком Cherry MX.
- U25 — по `case/policies/U25-CHECK-POLICY.md` и базе `case/accepted/2026-11-06-clean/U25-BASELINE-2026-11-06.json` (с 06.11.2026: верх/U25 58,210303 мм³, низ/U25 0). Рост ≤0,001 % от базы, уменьшение можно, новые пары нельзя; базу без решения пользователя не менять.
- Варианты печати (ориентация, вариант, скорость) выбираю сам по приоритетам пользователя и показываю выбор с обоснованием.
- Сначала показать результат, потом проверки; исключение — прямое разрешение на автономную серию (результат — кандидат).
- В отчётах при FAIL/UNVERIFIED: абсолютная ошибка с единицами, процент от явной базы, предел и отношение к нему. Неизмеренное не называть PASS.
- Изготовление, печать, публикация и `git push` — только по прямому разрешению.
